## 2. 原问题与根因

### 2.1 “优化器太严格”的真实组成

原逻辑不是单一阈值过严，而是多层重复惩罚：

- 生命周期成本在候选净值扣除后，又进入联合情景CVaR。
- LCB已经包含统计不确定性，组合层又扣一次模型不确定性。
- 个股尾部损失先求和作硬否决，组合层再用联合CVaR否决。
- 15元绝对成本和30%成本占比既作质量警告又近似成为硬门。
- 候选级尾部/集中度惩罚和组合级风险惩罚重复。

首轮20日中仅7/2,686条提案通过经济门。2025-01-27的`sh603650`一手候选保守净价值为12.2306元、权威折扣3.3590元，但0.05软CVaR系数再扣14.3692元，使最终目标变成-5.4976元；硬CVaR预算当时并未绑定。

### 2.2 “持仓不足”的跨模块根因

- `ActionPlan`计划持仓数曾被写成`target_holding_count`，优化器拒绝买入后会同步缩小目标，形成目标—计划循环。
- 普通建仓只有月度权限；低于下限时，恢复动作仍被研究型风险贡献门或月度日历拦截。
- Top-12候选压缩先按粗略分数/成本截断，丢失真实经济可行候选。
- D级无交易权限或`max_lots=0`候选占据Top-12容量。
- 非月度恢复单虽按恢复预算选出，却仍被记录为`normal_buy`并可能继承月度挂单窗口。
- 最终决策日新注册的pending订单只存在于内存，保存账本没有终态快照。

### 2.3 运行慢的根因

精确搜索不是唯一瓶颈。将组合候选限制到12后，逐全截面计算一手完整生命周期成本、权限折扣和情景风险仍占主要时间；保存阶段还要生成100个额外frame、诊断图和持仓因子工作簿。

## 3. 实施后的模型

### 3.1 仓位事实分层

永久分离以下事实：

- 战略目标、战略下界、战略上界；
- 硬风险上限；
- 当前整手/现金条件下可达上限；
- 优化器计划仓位；
- 成交后实际仓位。

三类缺口分别为：

`strategic_gap = max(strategic_target - actual, 0)`

`attainable_gap = max(min(strategic_target, attainable_ceiling) - actual, 0)`

`execution_gap = max(optimizer_plan - actual, 0)`

兼容字段`target_holding_count/holding_shortfall_count`只映射战略语义，不再由ActionPlan反推。

### 3.2 单一经济目标与单一组合风险

候选价值：

`candidate_net_value = notional × conservative_return - full_lifecycle_cost - authority_haircut`

组合目标：

`portfolio_objective = Σcandidate_net_value - λ×incremental_CVaR - concentration_soft_penalty - thesis_soft_penalty`

保留的硬门：

- 成本后保守净价值必须大于0；
- 生命周期成本/保守毛利不得超过60%；
- 现金非负、整手合法、单股结构上限；
- 组合CVaR硬预算、硬风险仓位上限；
- 停牌、涨跌停、T+1等事实交易约束。

消融/降级：

- 15元绝对成本和30%成本占比改为质量警告；
- 删除候选层重复尾部与集中度惩罚；
- 删除个股CVaR求和硬否决；
- LCB口径不再重复扣模型不确定性；
- 联合情景CVaR不再重复加入已扣生命周期成本。

### 3.3 仓位带与恢复权限

- 正常/中性：目标75%，下界60%，上界85%，硬上限90%。
- 弱势：目标55%，下界40%，上界65%，硬上限70%。
- 高风险：目标25%，下界0%，上界35%，硬上限35%。
- 危机：目标0%。
- 未知/无效状态按中性处理，不因缺失状态强制降仓。

低于条件下界且存在合格候选时，恢复获得独立权限：最多连续5个交易日、每天最多1个新名称、最多15% NAV。研究型风险贡献门只记录警告，不能否决恢复；事实安全门继续有效。无正价值候选时允许持币，但战略缺口不得归零。

### 3.4 搜索和记录

- 新入场搜索最多12只；最大持仓不超过5时允许精确枚举，其他情况使用宽度256的有界beam search。
- 截断顺序固定为：A/B/C且`max_lots>0` → 精确一手生命周期成本 → 60%硬成本占比 → Top-12 → 多手枚举。
- 非月度且非恢复日跳过新入场提案、协方差和同步情景构建，但保留持仓退出与安全动作。
- proposal/plan新增确定性`event_id/input_hash/formula_version/supersedes_event_id`。
- ActionPlan不再嵌套完整拒绝明细，仅保存ID并指向proposal账本。
- 非月度恢复单记录为`exposure_catchup_buy`，仅下一交易日有效。
- 保存前追加`terminal_state_snapshot`，确保最后一天新挂单不丢失。

下一步性能优化应限定为：

1. 同日证券规则、费率和一手交易金额缓存；
2. 一手生命周期成本向量化；
3. 将情景路径构建限制到权限通过且精确净值有希望的候选；
4. 缓存不随决策变化的因子研究图和工作簿中间结果；
5. 记录候选成本、场景构建、优化器、100个frame和工作簿的分段耗时。

不得用继续降低CVaR系数、删除生命周期成本或强制满仓来换取速度。
