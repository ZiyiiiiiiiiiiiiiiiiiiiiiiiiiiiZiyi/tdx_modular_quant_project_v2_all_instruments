# SCAP 2万元动态持仓数、费用吸血与赢家覆盖完整改进方案

## 1. 边界与结论

本报告只做设计审计，不修改策略、参数、数据、执行、会计、Web或报表代码，也不重新回测。依据为同一338日窗口的黄金版 `run20260730_232541`、新版 `run20260731_224446`，以及当前工作树静态代码。

核心结论不是“恢复固定5只”，也不是“继续允许最多13只就够了”，而是必须分开两个问题：

1. **可行容量上限**：现金、整手、流动性、风险和可选Web灾难护栏最多允许多少只。
2. **经济最优持仓数**：扣除完整生命周期成本、相关风险和估计误差后，今天新增第K只是否仍提高组合的稳健净终值。

当前代码只比较可靠地回答了第一个问题，却把这个上限直接传入单股预算和整数优化器。0.50%往返成本率只用于容量估算和报告，没有成为真实订单的准入条件；组合目标又是单提案稳健利润的近似线性求和，没有刻画“捕获至少一个有意义赢家”的概率、赢家能覆盖的组合亏损、相关性后的有效独立持仓数和未来换仓费用。因此，持仓可以扩到13只，但新增边际仓位未必有足够金额和质量。

## 2. 对用户观点的批判性判断

### 2.1 正确的部分

- 扩大股票覆盖面确实提高捕获稀有大赢家的机会。Bessembinder对美股长期横截面的研究表明，市场财富创造高度集中于少数股票；这支持“不能永久固定5只”的方向，但不能直接推出“持仓越多越好”。
- 本项目样本也支持“覆盖数量增加”：新版有59笔盈利交易，黄金版47笔，多12笔。
- 前180日黄金版+40.4386%、新版+16.0366%，后158日独立复利黄金版+9.5984%、新版+12.0097%。收益差主要形成于早期路径，不能把新版定义为在所有时期失效，也不应为了追平黄金版而对完整338日过拟合。

### 2.2 不完整或需要否定的部分

- “单只盈利覆盖多少只亏损”不能作为固定硬门槛。若直接最大化最大赢家/平均亏损，优化器会偏好低胜率、高正偏、类似彩票的候选；最大单笔收益还是高度不稳定的极值统计量。
- 正确对象应是**组合层面的概率覆盖**：在保留股票间相关性的情景中，盈利总额覆盖亏损和全部生命周期成本的概率与下分位，而不是要求某一只股票承担所有亏损。
- 13只是本次路径观察到的最大实际持仓，不是数学证明的最优上限。日级按持仓数分组的收益受行情状态和路径选择混杂：新版K=6的非连续日期复利较好、K=7较差，不能据此宣布“最优就是6只”。

## 4. 当前代码的直接原因

### 4.1 `capital_scaling.py`：经济门槛只存在于容量账本

当前最低经济订单为：

`N_min = 2 * minimum_commission / (c_max - 2*slippage - stamp - 2*transfer)`

以最低佣金5元、`c_max=0.50%`、双边滑点0.05%、卖方印花税0.05%、双边过户费0.001%计算，`N_min=2,873.56元`。但代码只把候选一手金额替换为 `max(one_lot_amount, N_min)` 后累加估算容量，并没有拒绝实际小于该金额的提案，也没有把订单放大到该金额。因此“小单经济门槛”当前是报告语义，不是交易语义。

### 4.2 `runner.py`与`scap_v31_authority.py`：上限K反向压缩所有单股仓位

自动模式把目标暴露近似按 `target_exposure / effective_position_cap`均分，并按K缩放单股软/硬上限。K越大，每个目标现金越小；当K=13且目标暴露约85%时，等权仅约6.54%，软上限约9.8%、硬上限约15%。这会把“允许更多候选”错误地变成“必须普遍稀释现有高质量赢家”。

### 4.3 `scap_v3_lean.py`：费用已扣，但风险与赢家概率表达不足

新开仓会计算真实往返成本，稳健利润近似为：

`decision_return * notional - round_trip_cost - risk_penalty - concentration_penalty`

但每只新仓的下行金额固定使用 `15% * notional`，不是候选自身、状态和持有期条件下的经验尾部损失；目标也没有显式的胜率下界、盈亏金额分布、赢家阈值或完整生命周期换手概率。对未来加仓/替换/退出的预期费用未在新开仓时统一计入。

### 4.4 `integer_action_optimizer.py`：正边际被近似成线性相加

组合稳健目标主要是提案稳健利润求和，再减权限、论点、协方差、集中度和部署惩罚。只要多个提案各自为正，线性求和会倾向继续加股票；但真实组合效用并不线性，因为股票相关、固定佣金非凸、赢家仓位被稀释、未来换手成本和尾部共振存在。当前338日协方差虽有278日标为adaptive，但全部ActionPlan仍使用每股压力后备且边际协方差罚金为0，相关性实际上没有控制持仓数。

### 4.5 `entry_calibration.py`、报表与Web

现有滚动校准能产生预测信任、有效样本、Rank IC和校准斜率，但质量门中的ECE仍缺乏有效证据；因此不能把未经校准的预测胜率直接升格为真实概率。报表当前能显示容量上限和最低经济金额，却不能回答：为何选择第K只、第K+1只为何被拒、组合费用预算、盈利覆盖概率、有效独立持仓数和赢家/探索资金分配。

## 5. 建议的数学与金融模型

### 5.1 第一层：只计算可行容量，不决定实际K

`K_feasible = min(K_cash_lot, K_liquidity, K_risk, K_search, K_web_optional)`

- Web硬上限继续留空，只有用户主动填写时才作为灾难护栏。
- 已有合法持仓可以被grandfather，不强制卖出；但不得因为已有13只，就继续用13稀释所有新目标。
- `K_feasible`是优化搜索边界，实际选择数记为`K_selected`。

对2万元、约85%—90%目标暴露和2,873.56元最低经济金额，单纯按现金只能支持约5—6个完整经济仓位。随着NAV增长，可行容量自然增加；高置信的一手例外可以使实际K略高，但必须明确标记和单独验证，不能让例外吞掉规则。

### 5.2 第二层：真实订单经济性准入

每个新增或增量订单计算完整生命周期成本：

`C_life = C_buy + P(exit<=H)C_sell + P(add)C_add + P(replace)C_replace`

同时满足：

1. `round_trip_cost / notional <= c_abs_max`，0.50%保留为绝对护栏；
2. `C_life / expected_gross_profit_LCB <= eta_cost`；
3. `robust_net_profit_CNY > uncertainty_hurdle_CNY`；
4. 整手、现金、T+1、价格限制、流动性和风险全部可行。

建议首轮研究网格而非直接硬编码：`eta_cost={20%,30%,40%}`；人民币不确定性门槛用最低佣金倍数 `{2,3,5}×5元` 加模型标准误；绝对往返费率 `{0.40%,0.50%,0.65%}`。最终值必须由滚动样本外选择，0.50%不是天然最优值。

### 5.3 第三层：候选的保守盈亏分布

只用决策日前已成熟样本，按信号族、行业/相关簇、市场状态和持有期估计：

`EV_i^rob = p_i^L * W_i^L - (1-p_i^L) * L_i^U - C_i^life`

- `p_i^L`：收缩后的胜率下界；
- `W_i^L`：盈利金额或收益的保守分位；
- `L_i^U`：亏损金额上界或95% Expected Shortfall；
- 样本不足、漂移、ECE不可用时fail closed到现有因子LCB和每股压力模型，不伪造0.5概率。

### 5.4 第四层：组合情景目标内生选择K

对同日候选使用保留横截面相关性的历史块/簇情景，优化：

`U(P)=E[log(1+R_P,net)] - lambda*CVaR95(-R_P,net) - gamma*EstimationUncertainty - LifecycleCosts`

采用对数终值是为了2万元账户防止过度下注；CVaR和估计误差防止只追逐极端赢家。第K只只有在：

`DeltaU_i = U(P ∪ {i}) - U(P) > hurdle_i`

时才接受；当所有剩余候选边际效用非正时停止。这样13只是可能的上界，不再是隐含目标。

### 5.5 把“赢家覆盖亏损”改为两个组合指标

1. **利润覆盖率PCR**：`sum(expected_positive_PnL) / (sum(expected_loss)+C_life)`；
2. **概率覆盖PCP**：`P(total_positive_PnL >= total_loss + C_life)`，由相关情景估计并保存下置信界。

“有意义赢家”应按人民币贡献定义，例如其净利润超过组合当期损失预算的一定比例，而不是只要收益为正。研究网格可测试 `PCR_LCB={1.10,1.25,1.50}`、`PCP_LCB={55%,60%,65%}`；它们只能作为组合健康门或软惩罚，不能未经样本外验证直接成为生产硬阈值。

### 5.6 资金结构：覆盖池与赢家池分权

- **探索/覆盖池**：建议研究25%—45% NAV，持有若干通过经济门槛的一手/初始仓位，目标是提高稀有赢家捕获概率。
- **核心/晋级赢家池**：建议研究40%—60% NAV，允许已验证赢家加仓；单股上限不再单纯按`1/K`压缩，而由个股风险、支持证据和组合核心池总预算约束。
- **现金/风险缓冲**：建议研究10%—20% NAV，保留退出、价格跳空和未来高质量机会的可用现金。

这些是实验区间，不是最终配置。探索股晋级核心必须经过独立的盈利加仓授权；亏损摊平继续关闭；退出模块全部保留，市场状态只做连续风险调节，不做二元总开关。

### 5.7 组合费用预算与低换手带

- 保存未来H日预计生命周期费用/NAV、费用/预计毛利润、已实现滚动费用/NAV。
- 引入no-trade band：边际效用改善未超过“固定费用+滑点+估计误差”时维持原仓，避免小幅排名变化反复换仓。
- 佣金档案由Web/券商账户配置；上交所公开页面给出佣金最高3‰、单笔最低5元，但真实账户费率可能不同，不能把5元最小佣金当成所有账户永恒事实。

## 7. 分阶段测试与验收

1. **先写失败测试与静态审阅**：逐模块`py_compile`；全文搜索证明最低经济金额确实进入提案/优化器，而非只出现在报告。
2. **费用阶段**：用1,000/1,500/2,873.56/5,000元手算沪深买卖费用；检验最低佣金拐点、卖方印花税、整手和分批加仓。任何低于门槛订单若成交，必须有可复算例外原因。
3. **PIT校准阶段**：人为未来收益变更不得改变当日概率；样本不足、ECE不可算、漂移时必须降级；不能将缺失概率填0.5后获得权限。
4. **容量阶段**：属性测试证明NAV、价格、现金、风险变化时`K_feasible`单调合理；`K_selected<=K_feasible`；已有持仓grandfather不产生强制卖出，也不提高新开仓额度。
5. **优化器阶段**：在小候选集上与完整穷举逐项对照；接受的最后一只`DeltaU>0`，新增任何被拒候选不得提高目标；固定随机种子可复现。
6. **覆盖阶段**：构造“多小亏+一大赢”“多相关赢家”“高胜率小赢但费用吞噬”“彩票型低胜率大赢”四类案例，验证PCR/PCP和对数效用不会被极值欺骗。
7. **生命周期阶段**：退出全部保留，赢家加仓、亏损禁加、T+1、现金、单股和池预算同时成立；无计划血缘订单必须为0。
8. **全回归**：运行现有capital scaling、cash cost、integer feasible、optimizer、Lean chain、lifecycle、runtime identity、summary、Excel、Web和phase-one验证；任何失败不得进入回测。
9. **20日工程全链**：从初始化、PIT、候选、ActionProposal、唯一ActionPlan、订单、成交、持仓、NAV、覆盖/费用账本到CSV/Excel/Web/manifest/COMPLETE保存。20日只证明工程，不判断盈利。
10. **受控研究实验**：固定代码指纹、日期、因子柜、PIT、费用和初始资金，做`fixed5`、当前auto、改进auto三臂；分别在前180日、后158日和滚动样本外报告。再做成本率、费用占毛利、探索/核心池和覆盖门槛的正交网格。

统计验收使用配对日收益、分块bootstrap置信区间、多参数族Holm校正，并报告收益、回撤、成本、换手、赢家遗漏率、PCR/PCP、实际K分布和风险模型覆盖率。338日已经参与诊断与设计，只能作为开发/审计窗口，不能再充当最终样本外证明。

## 8. 推荐实施顺序与停止条件

优先级为：真实订单经济门 → 生命周期费用账本 → `K_feasible/K_selected`解耦 → 候选PIT盈亏分布 → 组合边际效用/PCR/PCP → 赢家池 sizing → 报表/Web → 20日工程验收 → 长窗受控A/B。

若校准概率无有效样本、情景相关性覆盖不足、优化器不能与小集合穷举一致、或运行身份不能完整区分参数，则停止在研究状态，不允许用“强制满仓/强制凑持仓数”维持活跃度。目标不是复刻黄金版+53.9%，而是在未见数据上提高成本后对数终值，并保持退出保护与可审计性。
