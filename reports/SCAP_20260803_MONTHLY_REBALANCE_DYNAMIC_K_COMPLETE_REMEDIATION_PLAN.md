# SCAP 2万元账户：月度调仓、动态持仓与收益质量完整修改方案

## 1. 方案状态与边界

本方案针对 `run20260803_003104` 已确认的四条因果链：

1. 绩效基准的 `monthly` 被误解为组合月度调仓，而组合实际仍按周开放，confirmed/catch-up 买入还能绕过普通日历；
2. 2万元账户的动态上限被“一手现金可买数量”主导，最低经济金额只作警告，大量小单造成费用吸血；
3. 市场状态诊断关闭/无效时仍以默认 bear 对组合 ES 预算乘 0.75；
4. 长假前 pending 信号在复市日批量成交，持仓和暴露产生跳变；工作簿与因子运行审计还存在持仓日覆盖缺口。

本轮只冻结设计，不修改生产代码、不调整参数、不运行回测。实施必须在下一轮按阶段进行，每阶段均先做不运行生产回测的静态/数学审查，再做专项 bug 测试；全部阶段通过后才允许20日工程窗和338日研究窗。

## 2. 需要冻结的业务合同

### 2.1 调仓合同

- 组合普通选股与目标组合重建采用“月度决策”。默认锚点为每个自然月最后一个实际交易日收盘生成信号，下一可交易日开盘开始执行。
- `performance_benchmark_rebalance` 只描述绩效基准；新增独立的 `portfolio_normal_rebalance_frequency=monthly`，两者必须同时进入运行身份和报告。
- 止损、灾难止损、信号失败、论点失败、利润保护、安全降仓和市场交易权限卖出保持每日触发，不受月度日历限制。
- 月中 confirmed-entry 只能进入观察队列，不得产生新股票买单；月中 catch-up 只能继续执行同一个月度 ActionPlan 中未完成的目标手数，不得新增候选、改排名或提高原计划目标。
- 主动替换属于月度普通决策；只有风险卖出可以月中执行，卖出产生的现金不得自动触发月中新股票替换。

### 2.2 动态持仓合同

- 不恢复固定5只，也不把13只作为默认硬上限。
- Web 只保留可选 `user_hard_position_cap`，留空/0表示不加人为上限。
- 分离并落盘：`K_web`、`K_search`、`K_cash_feasible`、`K_cost_feasible`、`K_risk_feasible`、`K_effective_independent`、`K_feasible`、`K_selected`、`K_actual`。
- `K_feasible` 是金融可行上限，不是目标；`K_selected` 由整数优化器的正边际净效用内生决定。
- 已有合法持仓在上限下降时可以暂时祖父化，避免机械强平；但必须单列 `grandfathered_excess_names`，且月中不得再增加这些股票或新增其他普通仓位。

### 2.3 市场状态合同

- 不启用大盘二元总开关。
- 状态只能连续调整组合 ES 风险预算，不能改变选股排名、离散入场阈值、最大持仓数、普通调仓频率或关闭全部交易。
- 诊断器不存在、输入无效、PIT 日期不合法、基准/宽度覆盖不足或状态控制未授权时，乘数必须 fail-neutral 为 1.0。
- 有效状态证据下才允许乘数在预注册区间 `[0.70, 1.10]` 内连续变化。

### 2.4 收益质量合同

- 20日窗口只有工程验收权，没有盈利评价权。
- 策略改进不能只看总收益；必须同时报告前180/后158、滚动60/120日、极端日剔除敏感性、费用前后收益、持仓数分桶、暴露分桶、月度收益贡献和几何相对收益。
- 不允许根据本次338日表现反向挑选因子或阈值。参数必须来自预注册训练窗或滚动样本外估计。

## 3. 数学与金融模型

### 3.1 最终手数与完整生命周期费用

对候选股票 `i` 的整数手数 `q_i`，订单名义额为：

`N_i(q_i) = q_i × lot_i × execution_price_i`

完整生命周期费用必须按最终手数计算：

`C_i(q_i) = C_buy_i(q_i) + E_t[C_sell_i(q_i)] + C_impact_i(q_i) + C_opportunity_i(q_i)`

其中买入佣金与卖出佣金分别执行最低5元，卖出侧加入印花税，双边加入滑点、过户费和冲击成本。不得再用“一手费用率×总股数”或只按买入腿估算。

0.50%往返费率保留为诊断警戒，不再单独决定所有股票的硬最低名义额。真正的硬经济条件改为候选自身的利润、费用和风险联合约束。

### 3.2 稳健入场价值

只使用决策日前的滚动样本估计：

- 胜率 `p_i`；
- 条件平均盈利 `G_i`；
- 条件平均亏损 `L_i`；
- 预测不确定性 `sigma_mu_i`；
- 完整生命周期费用 `C_i(q_i)`。

毛期望人民币收益：

`EV_gross_i(q_i) = N_i(q_i) × [p_i G_i - (1-p_i)L_i]`

保守净收益：

`EV_robust_i(q_i) = EV_gross_i(q_i) - z × sigma_mu_i × N_i(q_i) - C_i(q_i)`

候选取得新增仓位资格至少同时满足：

- `EV_robust_i(q_i) > 0`；
- `C_i(q_i) / conservative_gross_profit_i(q_i) <= calibrated_cost_absorption_cap`；
- 盈亏平衡胜率 `p_break_even_i` 小于其收缩后胜率下界；
- 单名压力损失、组合 ES、自融资现金和整手约束均通过。

已有30%“生命周期费用/保守毛利润”上限可以作为初始冻结值进入A/B，但不得直接宣称最优；最终数值由滚动样本外净收益和稳定性选择。

### 3.3 动态持仓上限

每日金融可行上限定义为：

`K_feasible = min(K_web, K_search, K_cash_feasible, K_cost_feasible, K_risk_feasible, K_effective_independent)`

其中：

- `K_cash_feasible`：按候选证据顺序和最终整数手数累计扣减现金、最低现金缓冲与完整买入费用；
- `K_cost_feasible`：新增候选必须满足自身稳健利润覆盖完整费用，不能只看一手买得起；
- `K_risk_feasible`：联合情景下新增计划不得突破组合 ES/CVaR 预算和单名压力预算；
- `K_effective_independent`：根据持仓收益相关、风险贡献和有效因子家族计算的有效独立名称数，防止10只同一小市值风格被当成10份分散；
- `K_web` 为空时视为正无穷，不参与最小值。

实际持仓数由目标函数决定，而不是铺满 `K_feasible`：

`Delta U_i = Delta E[W]_i - lambda_ES Delta ES_i - lambda_U U_i - C_i - P_corr_i - P_conc_i`

只有新增第 `k` 只股票的边际效用为正，才允许 `K_selected=k`。每个已选和最佳被拒候选必须保存人民币目标分解，保证可复算。

### 3.4 组合风险

- 至少30个同日共同有效历史情景时，使用联合组合财富变化 `Delta W_s` 计算正式 CVaR/ES；
- 情景不足时只能标记为 `correlated_tail_loss_proxy`，不得宣称正式 covariance/CVaR；
- 协方差采用收缩估计，仅作为相关结构补充；缺失相关性不得填0冒充无风险；
- 市场状态乘数只作用于基础 ES 预算：`B_ES,t = B_ES,base × m_regime,t`；无效状态时 `m=1.0`。

### 3.5 单月决策与分期执行

月度 ActionPlan 在决策日一次生成并冻结候选顺序、目标手数、总现金和风险预算。执行层只做市场可交易性与现金事实阻断，不重新优化。

为避免0→5、3→6式单日跃迁，引入部署斜率：

`new_exposure_today <= min(remaining_plan_exposure, gap_risk_budget / stressed_gap_loss_rate)`

工程上同时设置预注册的“每日最多新增名称数/暴露比例”安全护栏，但初始数值只用于A/B，不凭本次结果优化。建议测试 2只/日与3只/日、25%与35% NAV 两组，不直接把其中任何一组写成生产最优值。

pending 订单每天检查：

- 是否仍在原月度计划；
- 信号年龄是否超过允许交易日；
- 价格跳空后稳健净收益是否仍为正；
- 完整费用、现金、涨跌停、停牌和风险预算是否仍可行。

失效则取消并记录原因，等待下一月度决策，不允许偷偷换入新股票。

## 4. 模块级修改方案

### Phase 0：缺陷夹具与运行身份

修改范围：`config.py`、`main.py`、`runtime_identity.py`、Web worker/表单、`runner.py`。

- 新增组合调仓频率字段，彻底与绩效基准频率分离；
- 运行身份加入组合频率、月度锚点规则、执行窗口、部署斜率、状态诊断启用/授权和无效状态后备值；
- 冻结8月3日三个失败夹具：非月度买入、状态关闭仍0.75、春节后0→5批量部署；
- 保留当前失败run不覆盖、不删除，作为回归证据。

静态验收：参数只有一个交易权来源；Web 文案不得把基准月度写成策略月度；相同身份必须确定性地产生同一月度锚点。

### Phase 1：月度日历和权限链

修改范围：`runner.py`、`policy.py`、`contracts.py`、`engine.py`、`pending_orders.py`。

- `_normal_rebalance_dates` 按自然月最后实际交易日构造；

- confirmed-entry 改为 watch-only；catch-up 仅对原计划剩余手数有效；
- 原因拆分为 `monthly_normal_buy`、`monthly_plan_catchup_buy`、`risk_exit` 等，禁止例外仍写 `normal_buy`。

专项测试：春节、国庆、月末停牌、月末非交易日、月末信号次日执行、月中止损、月中confirmed信号、跨月未完成订单。

### Phase 2：pending 新鲜度与部署斜率

专项测试：0→5被分期、长假跳空取消、涨停/停牌延迟、部分成交、最低佣金、T+1、现金不足、跨月自动失效。

### Phase 3：完整费用、动态K与整数优化

修改范围：`action_utility.py`、`capital_scaling.py`、`entry_calibration.py`、`scap_v3_lean.py`、`integer_action_optimizer.py`。

- `capital_scaling` 不再把一手可买数量命名为经济上限；

## 5. 每阶段固定测试程序

每个 Phase 必须按同一顺序执行：

1. 不运行生产回测的代码审查：交易权限、时间索引、单位、符号、缺失值、边界、不变量和上下游字段血缘；
2. 对修改文件执行 `py_compile`；
3. 运行该阶段最小构造夹具，覆盖正向、反向、边界和无效输入；
4. 运行受影响的现有专项脚本；
5. 做数学手算复核，误差不超过 `1e-9` 或明确的货币分位精度；
6. 做金融语义审查：费用是否双边、利润是否成本后、风险是否组合级、PIT是否只用过去、现金是否自融资；
7. 更新 WBS 证据，失败不得进入下一阶段。

## 6. 最终运行验收

### 6.1 20日工程全链

固定2万元、允许现金、Web硬上限空、月度组合频率、月度Top100基准、同一74因子柜和同一成本/PIT身份，从初始化运行到最终保存。

必须通过：

- checkpoint、manifest、COMPLETE 和 Web complete；
- 月中无普通新股票买入，风险卖出仍可发生；
- 月度Plan→order→pending→fill股数和现金守恒；
- 状态无效时乘数严格为1.0；
- 每日新增暴露不超过部署额度；
- 实际K不超过可行上限，祖父化单列；
- NAV独立重建、费用、T+1、暴露授权全部通过；
- 所有CSV可读，Excel Checks/公式/视觉全部通过。

20日只证明工程合同，不据此决定参数优劣。

### 6.2 338日同身份研究窗

在20日通过后运行338日，重点复核：

- 前180与后158独立复利；
- 月度普通买入次数、月中风险退出次数和换手；
- 平均/最大K、有效独立名称数、费用占本金和毛利润比例；
- 状态有效率与乘数分布；
- 正式联合情景CVaR激活天数；
- 最大1/5/10/20日收益贡献和极端日剔除收益；
- 退出分状态反事实；
- 研究基准几何相对收益和滚动beat ratio。

### 6.3 正交A/B矩阵

至少预注册以下单变量比较：

| A/B | 固定项 | 唯一变化 |
|---|---|---|
| A1/B1 | 代码、数据、成本、因子、PIT | 组合月度 vs 周度 |
| A2/B2 | 月度组合 | 部署斜率关闭 vs 开启 |
| A3/B3 | 月度+部署斜率 | 状态ES中性1.0 vs 有效连续状态 |
| A4/B4 | 其余全固定 | 候选经济硬合同旧版 vs 边际净效用新版 |
| A5/B5 | 其余全固定 | 简单1/N动态K基准 vs 优化器K |

任何版本只有在后158、滚动样本外、费用后收益、回撤和收益集中度共同改善时，才能称为模型提升。总收益单独变高不能作为通过条件。

## 7. 上线阻断条件

以下任一存在即保持 blocked：

- 组合频率与运行身份/报告不一致；
- 状态无效但乘数不等于1.0；
- 普通买入绕过月度合同；
- 计划手数、订单股数、pending或成交不守恒；
- 费用、风险或现金目标不能人民币复算；
- 实际暴露越过授权容忍；
- 因子共同结束日早于交易结束日且未fail closed；
- Excel Checks、公式或视觉验证失败；
- PIT L1/L2、冲击模型校准、滚动样本外矩阵、DSR/PBO/SPA证据不足。

## 8. 推荐施工顺序

推荐严格按 `Phase 0 → 1 → 2 → 3 → 4 → 5 → 6 → 20日 → 338日 → 正交A/B` 执行。

最先修复调仓身份与状态fail-neutral，因为它们是确定性合同错误；随后修复pending和部署斜率，阻止持仓突变；再调整动态K和费用数学。不要先根据+12.66%的结果调阈值，否则会把本次特定行情写进参数，增加过拟合风险。
