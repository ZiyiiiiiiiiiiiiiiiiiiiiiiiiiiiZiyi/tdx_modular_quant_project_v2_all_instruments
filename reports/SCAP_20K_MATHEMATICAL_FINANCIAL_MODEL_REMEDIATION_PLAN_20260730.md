# SCAP 2万元小资金数学与金融模型完整方案（只读设计稿）

> 日期：2026-07-30
> 状态：方案设计，不修改代码、不调整参数、不运行回测
> 基线：`small_capital_lean`，初始资金20,000元，100股整数交易，最低佣金5元，持仓上限由 Web/运行资本档案动态指定，允许持有现金

## 一、结论

2万元账户不能照搬连续权重的机构组合模型。真正的决策变量不是“目标权重”，而是每只股票买卖多少个整数手；交易费用、现金、槽位、停牌、T+1、卖出回款和风险预算必须直接在同一个人民币模型中求解。

推荐的新主模型是：

1. 账户层使用精确现金流和实际成交价格；
2. 决策层使用整数手数；
3. 收益层使用同一10日预测期限的稳健成本后人民币利润；
4. 风险层使用同期限情景损失/CVaR，协方差仅作已覆盖时的辅助风险模型；
5. 现金、槽位和风险是硬约束，部署率和持仓数量只能是次级软目标；
6. 没有足够成本后正收益机会时允许持有现金。

当前`small_capital_lean`的方向——整数手、最低佣金、允许现金、Web 动态持仓上限——是正确的；问题在于若干变量仍混用了市场暴露、现金需求、利润本金和风险罚金，导致模型虽然可运行，但目标函数不是严格自洽的金融模型。

## 二、外部规则和研究依据

### 2.1 A股整数交易约束

上交所现行《上海证券交易所交易规则（2026年修订）》自2026年7月6日起施行；普通竞价买入申报为100股或其整数倍，卖出不足100股的余额应一次性申报。深交所现行规则也要求按对应交易单位申报。

这意味着2万元账户必须使用整数/混合整数模型。把连续权重优化后再四舍五入，会改变现金、持仓数量、集中度、成本和预期利润，不是等价变换。

### 2.2 税费和固定成本

财政部、税务总局公告明确，自2023年8月28日起证券交易印花税减半征收。印花税只发生在卖出侧；佣金最低收费由券商合同决定，当前资本档案假设每边最低5元。

固定最低佣金使小订单的单位成本显著高于大订单。因此“多买几只以分散风险”并不总是免费：持仓越碎，每笔固定费用占比越高。

### 2.3 估计误差

Ledoit与Wolf指出，直接用于组合优化的样本协方差矩阵容易受到估计误差影响，建议采用收缩估计。DeMiguel、Garlappi与Uppal的样本外研究显示，复杂均值—方差模型未必能稳定战胜简单的1/N基准，原因之一就是均值和协方差估计误差。

这并不意味着应当永远等权，而是说明：

- 复杂优化器必须和简单的3只/4只等权或风险等额基准比较；
- 风险矩阵缺失时不能用0协方差假装“不相关”；
- 优化结果必须通过样本外、滚动块和留出期检验。

### 2.4 成本必须进入优化目标

Boyd等人的多期交易框架把预期收益、风险、交易成本和持仓约束放在同一个优化问题中。对本项目而言，重点不是使用更复杂的连续凸优化，而是遵守同一原则：现金流、费用和风险必须与收益处在相同期限、相同人民币单位中。

## 三、2万元账户的正确数学

### 3.1 四个不能混用的量

对股票`i`、执行价格`p_i`、每手股数`L_i`、交易手数`q_i`：

1. 市场金额：

   `market_notional_i = p_i × L_i × q_i`

2. 买入现金需求：

   `buy_cash_i = market_notional_i + buy_side_cost_i`

3. 卖出净回款：

   `sell_release_i = market_notional_i - sell_side_cost_i`

4. 市场暴露：

   `exposure_i = market_notional_i / NAV`

成本不能进入市场暴露分子，往返成本也不能全部进入买入现金需求；已经支付的买入费是沉没成本，退出时只能扣未来卖出侧费用。

### 3.2 当前费用假设下的精确成本函数

忽略市场冲击、假设买卖价格相同且成交金额为`N`，当前档案：

- 佣金率：0.03%，每边最低5元；
- 滑点：每边0.05%；
- 过户费模型：每边0.001%；
- 卖出印花税：0.05%。

则：

`round_trip_cost(N) = 2 × max(5, 0.0003N) + 0.00152N`

对2万元账户常见订单：

| 单次市场金额 | 估计往返成本 | 成本率/盈亏平衡收益 |
|---:|---:|---:|
| 2,000元 | 13.04元 | 0.652% |
| 3,000元 | 14.56元 | 0.485% |
| 4,000元 | 16.08元 | 0.402% |
| 4,750元 | 17.22元 | 0.363% |
| 5,000元 | 17.60元 | 0.352% |
| 6,000元 | 19.12元 | 0.319% |
| 8,000元 | 22.16元 | 0.277% |

仅从费用看，低于约2,900元的订单，往返成本率会超过0.5%；约4,000元以上才接近0.4%以内。因此2万元账户的经济持仓通常是3—4只，但这只是经济性建议，不是代码硬上限；最终硬上限以 Web 提交值为准。

### 3.3 账户净值和基准数学

账户净值：

`NAV_t = cash_t + Σ shares_i,t × valuation_price_i,t - liquidation_cost_proxy_t`

账户相对基准的几何收益必须是：

`relative_wealth_t = NAV_account,t / NAV_benchmark,t`

`geometric_excess_return_t = relative_wealth_t - 1`

等价形式：

`Π[(1+r_account,t)/(1+r_benchmark,t)] - 1`

下列两个指标可以保留，但必须改名：

- 简单总收益差：`R_account - R_benchmark`
- 每日算术主动收益链：`Π[1 + r_account,t - r_benchmark,t] - 1`

二者都不能命名为几何相对财富。

## 四、建议的2万元专用组合模型

## 4.1 决策变量

每个股票只允许选择一个最终手数：

`q_i ∈ {0,1,...,q_i,max}`

卖出、持有、新开仓和加仓都转化为“当前手数→目标手数”。这比为同一股票建立多个可能互相叠加的proposal更容易证明现金和持仓约束。

### 4.2 稳健收益

对统一的10日预测期限：

`mu_robust_i = shrinkage_i × mu_point_i - kappa × forecast_SE_i`

`expected_net_profit_i(q_i) = market_notional_i(q_i) × mu_robust_i - incremental_exact_cost_i(q_i)`

其中：

- `shrinkage_i`由校准覆盖、样本量、authority tier和漂移状态决定；
- `forecast_SE_i`必须是相同10日期限；
- 未观测、过期或缺乏PIT证据时直接不可交易；
- authority不再通过另一个难以解释的人民币罚金重复扣减，而应主要体现在预测收缩或最大手数。

新开仓至少满足：

`expected_net_profit_i > 0`

工程初始保护条件可增加：

`robust_gross_profit / exact_round_trip_cost >= 2`

“2倍成本覆盖”只是建议的初始研究门槛，必须通过滚动样本外实验校准，不能直接宣布为最优参数。

### 4.3 风险目标

建议把主要组合风险统一为10日人民币情景损失，而不是同时叠加固定15% downside、协方差罚金、集中度罚金和压力预算。

对历史/因子压力情景`s`：

`loss_s(q) = -Σ market_notional_i(q_i) × scenario_return_i,s + scenario_execution_cost_s`

计算：

`CVaR_95(q) = E[loss_s(q) | loss_s(q)位于最差5%]`

主目标：

`maximize Σ expected_net_profit_i(q_i) - lambda × CVaR_95(q)`

集中度、thesis和authority若已经改变情景损失或预测收缩，不应再次重复罚同一种风险。

### 4.4 硬约束

1. 精确现金：

   `cash_after = cash_before + Σ sell_release_i - Σ buy_cash_i >= cash_buffer`

2. 总暴露：

   `Σ market_notional_i / NAV <= hard_exposure_ceiling`

3. 持仓数量：

   `Σ 1(q_i>0) <= K_web`，其中`K_web`来自本次Web运行资本档案

4. 单股风险：

   `position_weight_i × effective_stop_distance_i <= per_name_risk_budget`

5. 账户总开放风险：

   `Σ position_weight_i × effective_stop_distance_i <= total_open_risk_budget`

6. 已有持仓无论是否出现在候选表，都必须进入`q_i,current`和槽位计数。

7. 强制退出必须先执行；替换必须是原子配对，买腿和卖腿不能只执行一边。

### 4.5 目标函数的优先级

建议使用真正可解释的词典序：

1. 执行强制安全退出；
2. 满足现金、持仓、风险、交易规则和T+1硬约束；
3. 最大化稳健成本后人民币目标；
4. 在目标值接近时降低CVaR和费用；
5. 最后才考虑广度和部署率。

部署不足不能把负收益交易变成正收益交易。现金是合法资产，不应为了达到90%目标仓位强制买入。

## 五、推荐的2万元研究型风险档案

以下是待验证的工程起点，不是收益承诺或最终参数：

| 项目 | 当前值 | 建议研究起点 | 理由 |
|---|---:|---:|---|
| 初始资金 | 20,000元 | 保持 | 用户资本约束 |
| 基础现金缓冲 | 1,000元 | `max(1,000元, 5% NAV)` | 保留费用和执行误差空间 |
| 经济持仓目标 | 软目标4、当前档案默认上限5 | 3—4只仅作经济性建议；硬上限由 Web 动态指定 | 兼顾固定费用、分散和未来扩展 |
| 单股软上限 | 25% | 20%—25% | 一手离散下的目标带 |
| 单股硬上限 | 40% | 30% | 40%×18%会产生7.2%账户损失 |
| 正常市场期望暴露 | 90% | 80%—85% | 给整数手和下一次机会留空间 |
| 正常市场硬上限 | 安全上限 | 90% | 与软目标分离 |
| 协方差冷启动暴露 | 未统一 | 不高于65% | 风险未知时降低而非假装0相关 |
| 单股开放风险预算 | 未统一 | 2.5%—3.0% NAV | 每只最大计划损失约500—600元 |
| 总开放风险预算 | 未统一 | 8% NAV | 控制多只同时触发风险 |
| 回撤预警 | 30% | 10% | 2万元账户先控制资金生存 |
| 新开仓冻结 | 40% | 15% | 现值相当于损失8,000元，过晚 |
| loser add | 关闭 | 保持关闭 | 在模型证据不足前避免负凸性 |
| active replacement | 关闭 | 保持关闭 | 先证明原子配对和净边际收益 |
| force deploy | allow cash | 保持allow cash | 禁止ActionPlan后补单 |

风险预算会产生一个重要、但正确的结果：某些高价或高波动股票即使信号很好，也可能因为一手风险超过预算而不可买。对于2万元账户，这是资本约束，不是程序失败。

举例：单股风险预算600元，若有效止损距离为12%，最大市场金额为5,000元；若止损距离为18%，最大市场金额只有3,333元。100股价格超过相应上限时，应持有现金或选择风险更合适的股票，而不是突破风险预算。

## 六、协方差和风险模型方案

### 6.1 使用条件

只有同时满足以下条件才允许ActionPlan写`risk_model_used=covariance`：

- runtime maturity不是cold-start；
- 最终持仓和所有拟买股票的方差覆盖100%；
- 最终组合的两两协方差覆盖100%；
- 估计矩阵通过对称、有限值和半正定检查；
- 风险期限明确换算到10日。

否则必须写明确的fallback名称和原因。

### 6.2 推荐估计

1. 用决策日前数据；
2. 采用Ledoit–Wolf式收缩，不使用裸样本协方差；
3. 建议比较60、120、252日窗口，以样本外损失和稳定性选择，不按单次收益挑选；
4. 对候选池和最终选中集合分别记录覆盖；
5. 缺失股票进入因子/行业/市场压力情景fallback，不能把未知协方差填0。

对于 Web 指定的少量持仓组合，情景压力/CVaR比在大候选集上追求精细协方差逆矩阵更稳健。协方差可以用于识别共振风险，但不应成为唯一风险表达。

## 七、逐项缺陷的模块级方案

### 7.1 基准收益

- 模块：`analytics.py`、`runner_summary.py`、图表和Web字段。
- 方案：分别保存几何相对收益、简单总收益差、每日主动收益差链。
- 验收：用两天手算例验证三个指标不同；账户和基准相同时几何相对收益严格为0。

### 7.2 风险模型状态

- 模块：`runner._rolling_candidate_covariance`、runtime maturity、optimizer、ActionPlan。
- 方案：传递`coverage_symbols/pair_coverage/maturity/fallback_reason`，由最终选中集合决定`risk_model_used`。
- 验收：任一选中股票缺覆盖时不得写covariance；缺失协方差不得变成0风险。

### 7.3 整数可行暴露

- 模块：`scap_v3_lean.py`、`integer_action_optimizer.py`。
- 方案：废除逐只“单独买得起”的近似；直接从最终整数可行计划读取可部署暴露。
- 验收：累计现金、已有槽位、最低佣金和多手费用全部进入同一手算案例。

### 7.4 signal-supported口径

- 方案：只有authority收缩/不确定性处理后，稳健成本后利润为正的提案才进入信号支持集合。
- 验收：罚前为正、罚后为负的提案不得提高目标暴露或部署缺口。

### 7.5 优化目标分解

- 方案：ActionPlan保存`gross_forecast_profit`、`forecast_uncertainty`、`exact_cost`、`scenario_CVaR`、`thesis_penalty`、`deployment_penalty`和最终目标；各项必须相加完全闭合。
- 验收：每个计划允许以CSV字段重建目标，误差不超过1分钱。

### 7.6 最优性

- 方案A：对2万元账户使用按股票分组的精确分支定界/多选择背包；维度直接取 Web 运行时持仓上限，并输出原始提案数、剪枝证明和最优间隙。
- 方案B：若继续启发式裁剪，字段只能写`optimal_within_reduced_universe`，不得写全局最优。
- 验收：构造最低佣金导致“两手优于一手”的反例，保证裁剪不丢失真实最优方案。

### 7.7 ActionPlan后补单

- 模块：`runner.py`。
- 方案：Lean模式中所有订单必须来自最终ActionPlan；force-deploy只能生成proposal并重新调用唯一优化器，不能在计划后追加订单。
- 验收：所有order/fill proposal ID必须属于selected proposal集合。

### 7.8 卖出回款

- 方案：使用真实当前股数、预计卖出价和卖出侧精确费用；买入沉没成本不再重复扣减。
- 验收：一手、多手、零股、最低佣金、印花税和部分成交分别手算。

### 7.9 持仓缺失候选

- 方案：账户持仓是状态真源；候选表只提供预测信息。停牌/缺数持仓仍占槽位和暴露，且只能产生持有或受约束退出。
- 验收：持仓从候选表消失时，不得多开第6只股票。

### 7.10 loser add、replacement和authority

- loser add必须同时满足生命周期、review、authority、冷却、尾部风险和总风险预算；初期继续关闭。
- replacement只有在生成完整配对proposal且净边际收益覆盖双腿费用和风险变化后才能开启；初期继续关闭。
- authority缺少正式校准字段时生产路径fail-closed；synthetic compatibility只允许显式测试模式。

### 7.11 事后利润审计

- `forward_return_20d`结果改名为`counterfactual_forward_20d_*`；
- 实际利润只能来自真实fill、费用、公司行动和trade-pair；
- 开放持仓另列未实现盈亏，不得与已实现利润混合。

## 八、施工顺序

### Phase 0：冻结和失败测试

黄金版本已经冻结。先为每个缺陷建立必然失败的最小测试，不改变策略。

### Phase 1：报表和字段语义

先修基准数学、反事实字段名称和目标分解。这一阶段原则上不应改变订单。

### Phase 2：账户与费用原语

建立唯一的市场金额、买入现金、卖出回款、买卖费用接口，删除规划层的近似重复公式。

### Phase 3：整数优化器

改为股票级目标手数、累计现金、真实槽位和风险预算；移除不真实的全局最优声明。

### Phase 4：风险模型

实现覆盖率、maturity、收缩协方差和fallback情景；禁止未知协方差填0。

### Phase 5：动作权限

关闭ActionPlan后旁路；补齐停牌持仓、加仓、替换和authority fail-closed。

### Phase 6：全链验收

按以下顺序：

1. 纯函数手算测试；
2. 不运行策略的静态代码审查；
3. 每模块专项bug测试；
4. 5日零交易/单交易构造窗口；
5. 同spec 20日全流程；
6. 180/338日工程回归；
7. 滚动块、留出期、成本压力和参数扰动；
8. 与3只等权、4只等权、持有现金基准比较。

## 九、研究准入门

工程正确不等于策略有效。建议至少满足：

- 计划目标100%可由账本重建；
- proposal→plan→order→fill→PnL血缘100%；
- 账户NAV逐日重建误差不超过1分钱；
- 协方差实际覆盖和字段声明一致；
- 不同成本压力下不由正收益立即翻成严重负收益；
- 至少30笔闭合交易后才解释profit factor；
- 滚动/留出期成本后期望为正；
- 相对3只/4只简单基准的改善在多个窗口稳定，而不是单个20日窗口偶然领先；
- 研究门通过前不得把20日年化收益或Sharpe用于上线判断。

## 十一、最终建议

优先修正“数学真值”和“风险真值”，暂时不要调因子权重、止损阈值或追求更高仓位。对2万元账户，最重要的不是把资金用满，而是确保每一次100股整数交易在真实费用、预测不确定性和组合共振风险之后仍有正的人民币边际价值。
